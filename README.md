# 亮切工坊 · 网页版（Docker）

> ⚠️ 仅供个人学习与技术交流，请自行遵守抖音平台规则与相关法律法规，使用产生的后果自负。

Windows 桌面版「亮切工坊」的完整 Docker 化移植：业务逻辑（采集 / 剪辑 / 发布 / 申诉 / 企微互通）
原样保留，Tkinter 界面 1:1 重做成网页，Chrome 浏览器跑在容器里的虚拟屏幕上，网页里可以直接看到、
可以操作（扫码登录、人工接管脚本都和原来一样）。

## 界面入口

| 入口 | 地址 | 用途 |
|---|---|---|
| 操作界面 | http://localhost:8000 | 和桌面版一样的四个页面 + 设置 + 企微互通 |
| 浏览器画面 | http://localhost:6080/vnc.html | 容器里的 Chrome 画面（也可在界面里点「浏览器画面」） |
| 企微回调 | http://你的IP:8443/wecom | 配置企微互通远程指令时填到企微后台 |

## 快速开始

**方式 A · 直接用发布好的镜像（推荐，免构建）**

```bash
git clone https://github.com/frank3101/liangqie-studio.git
cd liangqie-studio
docker compose up -d          # 自动拉取镜像，几分钟内跑起来
```

**方式 B · 自己构建镜像（改过源码的开发者）**

编辑 `docker-compose.yml`：注释掉 `image:` 行，取消 `build:` 段的注释，然后：

```bash
docker compose up -d --build
```

**启动后**：打开 http://localhost:8000 → 首次访问设置登录密码 → 「新增账号」→ 打开浏览器 → 在「浏览器画面」里扫码登录抖音。

> 方式 B 首次构建要装 Chromium / 字体等系统包，需要几分钟。
> 数据全部落在 `./data` 目录（挂载为容器里的 /data），升级镜像、重建容器都不丢。

## 容器里装了什么

- **Chromium**：被脚本 CDP 接管的浏览器，每个账号独立 user-data-dir（和桌面版一样的隔离方式）
- **Xvfb + x11vnc + noVNC**：虚拟屏幕，让 Chrome 窗口在网页里可见、可点击
- **ffmpeg**：剪辑用（剪辑模块自动使用，无需配置）
- **中文字体（Noto CJK）**：保证 Chrome 里抖音页面正常渲染中文

## 和桌面版的差异

| 桌面版 | 网页版 |
|---|---|
| 双击 亮切工坊.exe | 打开 http://localhost:8000 |
| Chrome 窗口直接弹出 | Chrome 开在「浏览器画面」页里（网页里可操作） |
| 「打开目录」弹资源管理器 | 弹网页文件浏览（点文件可下载） |
| 文件选择框导入 CSV/Excel | 已替换为「从选品车导入商品」（自动打开百应选品车页面抓取；采集剪辑完一个商品后自动把它从选品车移出） |
| 后台线程弹「是/否」确认框 | 网页顶部弹同样的确认框，任一浏览器点「是」都生效 |
| profiles/ 在 exe 旁边 | profiles/ 在 data/ 卷里（`python migrate.py` 自动搬） |

其余功能一一对应：账号管理（增删改/导入/打开浏览器/检测登录/关闭）、素材采集与剪辑
（橱窗导入、选品车导入、补全信息、一键采集+剪辑、清除空壳文件夹）、作品发布（扫描、
生成文案、复制AI提示词、粘贴导入、定时/立即发布、演练、清除已发布）、作品申诉
（规则编辑、扫描、一键申诉、复查队列）、企微互通（Webhook 推送 + 远程指令）全部保留。

## 挂载额外硬盘 / NAS（素材目录、申诉材料放 NAS 上）

素材目录和申诉材料通常放在 NAS 或第二块盘上，需要先把那块盘"映射"进容器，网页里才能填它的路径。

### 1. 改映射

编辑 `docker-compose.yml` 的 volumes，或复制 `.env.example` 为 `.env` 后填路径（更省事）：

```ini
# .env
MEDIA_HOST_1=Z:/素材              # Windows 已映射成盘符的 NAS（Z: 是网络驱动器），注意用正斜杠
MEDIA_HOST_2=D:/申诉材料          # 第二块本地盘
DS_EXTRA_ROOTS=/mnt/media1:/mnt/media2
```

```yaml
# docker-compose.yml（默认就是这样，用 .env 覆盖 source 即可）
- type: bind
  source: ${MEDIA_HOST_1:-./mnt/media1}
  target: /mnt/media1
- type: bind
  source: ${MEDIA_HOST_2:-./mnt/media2}
  target: /mnt/media2
```

- `source` 是宿主机路径（盘符 / 共享路径），`target` 是容器里的路径
- 这里用的是 long syntax（`type/source/target`）而不是 `Z:/素材:/mnt/media1` 这种简写 —— Windows 盘符带冒号，
  简写会被拆错，务必保持 long syntax 写法
- `DS_EXTRA_ROOTS` 是网页「选择目录」能进入的范围，必须包含上面的容器内路径，多个用冒号分隔
- 想加第三块盘：再写一行 volumes，并把新路径追加进 `DS_EXTRA_ROOTS`

> **Windows 上挂网络驱动器**：Docker Desktop 只能挂载「已经映射成盘符」的路径。
> 先在资源管理器里 `映射网络驱动器`（或用 `net use Z: \\nas\素材 /user:账号 密码`），
> 确认 `Z:` 能打开后，compose 里写 `Z:/素材`。
> 如果容器进不去或报权限错误，改用文件底部的**方式 C（CIFS 直挂）**，不经过盘符，更稳。

### 2. 重启容器

```bash
docker compose up -d
```

启动后「账号管理」的运行日志会打印每块挂载的状态（`已挂载：/mnt/media1` 或 `未挂载`），先看这里最省事。

### 3. 在界面上设置

| 页面 | 字段 | 填写内容 |
|---|---|---|
| ① 素材采集与剪辑 | 输出目录 | `/mnt/media1/素材输出` |
| ② 作品发布 | 素材目录 | 同上（一般和素材模块共用） |
| ③ 作品申诉 | 材料根目录 | `/mnt/media2/申诉材料` |

点输入框旁边的「**选择目录**」可以进文件浏览器直接点选，确认后自动保存；也可以直接手打路径后点别处保存。
保存时会立刻校验：目录不存在 / 没挂载 / 不可写，都会弹提示并说明原因，不会写入无效配置。

### NAS 挂载常见问题

- **提示"这个目录没有挂载进容器"**：说明 `DS_EXTRA_ROOTS` 里没有这个路径，或 volumes 写错，改完 `docker compose up -d` 重启。
- **提示"目录存在但没有写权限"**：CIFS/NFS 挂载要带 `uid=0,gid=0`（容器里是 root 运行）。
- **NAS 重启后目录变空 / 消失**：容器不会自动重挂。`docker compose restart` 即可；CIFS 方案建议在 NAS
  上把共享设为固定 IP 访问。
- **性能**：剪辑要大量读写，毛料/成品建议放本地盘，NAS 只放归档；实在要走 NAS 请用以太网而不是 Wi-Fi。

## 企微远程指令

配好「企微互通」的回调（Token / AESKey / CorpID + 8443 端口可达 + 允许成员）后，在企微里发消息即可控制：

| 指令 | 作用 |
|---|---|
| `状态` | 回：各账号今日已发/剩余、待发布成品数、任务是否在跑 |
| `发布` | 按网页里当前配置**立即**发布（全部账号 × 全部待发布成品） |
| `定时发布 11-25 07:00` | 现在开跑，但每条作品在抖音后台设成该时间**定时发布** |
| `采集` | 一键采集 + 剪辑（用当前商品清单） |
| `剪辑` | 只补剪成品数量不够的商品 |
| `申诉` | 回一份待申诉清单，回复 **`确认`** 才真正提交（10 分钟内有效，`取消` 放弃） |
| `停止` | 停止发布 / 素材任务 |
| `帮助` | 回指令说明 |

**定时只认绝对时间**，不支持"明天""3 天后"这类相对说法：

- `定时发布 11-25 07:00`、`定时发布 11月25日 7:00`、`定时发布 2026-11-25 07:00` 都可以
- 不写年份 = 今年；只写 `07:00` = 今天（已过会提示补日期）
- 抖音后台限制：最多提前 **14 天**，超了会直接回提示
- 写错时间会回一条说明（例如"时间看不懂。格式：定时发布 11-25 07:00"），不会瞎猜

发布失败、批次结束、申诉结果都会自动推回群里。

## 申诉材料怎么放

设置里的「申诉材料目录」（默认 `data/申诉材料`）就是材料根目录，按下面放：

```
申诉材料/
  ├─ 账号A01/          ← 每个账号一个子目录（命名 = 「账号」+ 账号名）
  ├─ 账号A02/
  └─ …
```

- **只认图片**：`jpg / jpeg / png / webp / bmp`，一般放肖像授权书、资质截图等 1~5 张
- **上传顺序 = 文件名顺序**：用数字前缀控制，如 `1_授权书.jpg`、`2_身份证.png`
- **按规则分目录**：申诉规则可设「材料子目录」，设置了就放 `申诉材料/<子目录>/账号A01/`；不设就直接用 `申诉材料/账号A01/`
- 目录为空的账号程序会**拒绝提交**并写日志提示，不会瞎申诉
- 「清除已发布素材」删的是素材输出里的商品目录，**不影响申诉材料**

## 常见问题

| 现象 | 处理 |
|---|---|
| 构建卡在 apt / pip | 换国内源或配代理；`docker compose build --no-cache` 重试 |
| 启动后 8000 打不开 | `docker compose logs` 看 uvicorn 是否报错；端口冲突改 compose 左边端口 |
| 浏览器画面一片黑 | 等 3–5 秒（Chrome 首次启动慢）；仍黑则 `docker compose restart` |
| 点「打开浏览器」没反应 | 看日志是否"没找到 Chrome / Chromium"；容器里路径是 `/usr/bin/chromium`，`CHROME_PATH` 已配好 |
| Chrome 里中文变方框 | 镜像里已装 Noto CJK，若自己改过 Dockerfile 记得保留 `fonts-noto-cjk` |
| 账号打开后要求重新登录 | Windows 登录态与容器 Chromium 版本差异，扫码重登一次即可（profiles 在 data/ 里不会丢） |
| 素材/申诉目录报"没有挂载进容器" | 见上面「挂载额外硬盘 / NAS」一节 |
| 剪辑报 ffmpeg 相关错误 | `docker compose exec liangqie ffmpeg -version` 验证；镜像已内置 |

## 常用命令

```bash
docker compose up -d --build   # 构建/更新并启动
docker compose logs -f         # 看日志
docker compose restart         # 重启
docker compose down            # 停止（数据在 ./data，不会丢）
```

## 注意事项

- **登录态迁移**：Windows Chrome 的 profile 可以直接被容器里的 Chromium 读取（migrate.py 已处理）。
  如果某个账号打开后提示配置异常，在该账号的浏览器里重新登录一次即可（登录态文件都在 data/profiles）。
- **企微互通回调**：容器已映射 8443 端口；路由器把外网端口转发到本机 8443，企微后台回调 URL 填
  `http://你的域名或IP:8443/wecom`。
- **端口占用**：8000 / 6080 / 8443 被占用时改 docker-compose.yml 左边的端口即可。
- **内存**：多开 Chrome 建议 Docker 分配 4GB 以上内存；compose 里 shm_size 已设 1GB。
- 想把整套界面放到公网或内网其他机器访问，8000 端口就是完整界面（无鉴权，注意别暴露公网，
  或自行加反向代理 + 密码）。
